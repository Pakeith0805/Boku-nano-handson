# Dataset Card: Boku-nano synthetic dataset

日本語の指示から整数リストを処理する `solve(xs, k)` を生成するための合成データセットです。意味ASTと正解コードはルールで作り、日本語の言い回しには教師モデルの候補を人間が査読した辞書を使います。

## 対象タスク

24種類の操作（抽出10、変換8、並べ替え3、切り出し3）を重複なく1〜4個並べます。入力は長さ0〜20、要素−100〜100の整数リストと、1〜10の整数 `k` です。出力の整数は入力の値域を超えても構いません。

正解コードは `def solve(xs, k):` の関数定義で、型注釈の有無にはバリエーションがあります。`k` のリテラル具体化台帳は使わず、必要な操作は引数 `k` を参照します。

## 保存済みデータの規模

2026-09-22に手元のJSONLを集計した値です。5ファイル合計は **1,010,707行** です。

| ファイル | レコード数 | 異なるAST数 | サイズ |
| --- | ---: | ---: | ---: |
| `train.jsonl` | 820,763 | 52,000 | 約1.09 GiB |
| `val.jsonl` | 95,164 | 6,500 | 約132 MiB |
| `test.jsonl` | 94,720 | 6,500 | 約131 MiB |
| `test_combination.jsonl` | 30 | 30 | 約43 KiB |
| `test_paraphrase.jsonl` | 30 | 30 | 約42 KiB |

特殊テストの生成上限は各30件ですが、候補不足や重複排除で減る場合があります。言い換えテストのASTは通常のtest分割母集団から選び、通常testとASTが重なる場合があります。

## 分割の方法と保証範囲

最初に `{even, desc}`, `{add_k, take_first}`, `{gt, reverse}` のいずれかを両方含むASTを隔離します。該当する16,962 ASTは組合せテスト用の**母集団**で、全件をテストファイルへ出すわけではありません。その中から最大30 ASTを使います。

残りを `behavior_hash` のグループ単位でtrain/val/testへ割り当てます。ただし固定入力上で常に空になる `always_empty` は例外で、ASTごとに分けます。その後、各splitで難易度1〜3を残し、4を間引いて合計65,000 ASTを目標にします。

この分割は通常ASTの同じ挙動が通常3splitを跨ぐのを防ぎますが、退化例は例外です。組合せテストと通常splitの挙動重複も除去しません。コード文字列の重複除去は各出力ファイル内だけで、全split横断の重複排除ではありません。

言い換えテストには辞書のID末尾が11以降の表現だけを使います。通常train/val/testと組合せテストは1〜10を使います。保留表現のあるopだけを対象にするので、24op全体を一様に評価する集合ではありません。

## フィールド

形式を組み立てるのは [src/select/record.py](../../src/select/record.py) です。AST台帳用の `src/semantics/schema.json` とは別の形式です。

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `spec_id` | str | `task-000001` のような通番。同じ生成実行の5ファイルを通して一意 |
| `ast_id` | str | `data/asts.jsonl` への引き当てキー |
| `semantic_ast` | list[str] | 元の操作列。定数は含まない |
| `instruction_ja` | str | 日本語指示文 |
| `reference_code` | str | 関数定義を含むPythonコード全文 |
| `phrase_ids` | list[str] | 辞書で使った言い回しIDをAST順に並べたもの |
| `tests` | list | 常に空。実行入力は別の凍結probe setから読む |
| `difficulty` | int | 操作数1〜4 |
| `code_style` | dict | 構造フラグ6個と変数名2個の計8フィールド |
| `semantic_hash` | str | 元の操作列の正準JSONのSHA-256 |
| `text_hash` | str | 指示文のSHA-256 |
| `teacher_model`, `teacher_revision` | str | 言い回し候補生成に使ったモデルとrevision |
| `prompt_hashes` | list[str] | 由来表から取得できたプロンプトハッシュの重複なし・ソート済みリスト |
| `verification` | dict | `syntax_ok`, `ast_safe`, `tests_passed` の真偽値 |

`code_style` の構造フラグは `comprehension`, `temp_vars`, `reverse_style`, `one_line_return`, `annotate`, `reordered`、変数名は `elem_name`, `var_name` です。効かないフラグもあるため、例えば `one_line_return=true` が常に1行形式を意味するわけではありません。

`reordered=true` は隣接filterの順序をコード側で変更したことを表します。レコードの `semantic_ast` とハッシュは元の操作列のままです。表現の由来が欠けていても `prompt_hashes` は取得できた分だけになり、生成は停止しません。

## 作成方法

```text
全AST台帳 + 承認済み辞書 + 言い回しの由来 + 凍結入力集合
  → 予約ペアの隔離
  → 通常3splitへの分割
  → 難易度4の間引き
  → コード・指示文候補の選抜（1 ASTあたり最大20例）
  → 検証結果を記録
  → ファイルごとにコード文字列の重複除去
  → 通番を振り直してJSONL保存
```

コード候補は内包表記/ループ、一時変数、逆順方式、return形式、型注釈・コメント、filter順序を変えます。選抜後に変数名を乱数で決めます。採用数の調整はワーカーごとのチャンク内で行い、構造フラグ6個の組全体と、各言い回しIDの採用数を参照します。

指示文は承認済み辞書279表現から選び、最後以外を連用形にしてつなぎます。各レコードを人間が個別に書くことはありませんが、**辞書の査読には人間の判断が入っています**。日本語の意味の正しさをコードの実行検証で確認しているわけではありません。

trainの難易度別レコード数は1: 180、2: 6,486、3: 153,693、4: 660,404で、均等ではありません。全AST台帳は各opを同数含みますが、隔離・選抜後の頻度を均等にする追加処理はありません。

## 検証と評価

生成時は構文・シグネチャを検査し、凍結入力148件で参照インタプリタの出力と比較します。許可する属性は `.append` で、属性アクセスを全面禁止しているわけではありません。実行例外・タイムアウト・不一致は `tests_passed=false` になります。

保存済みの全1,010,707行を確認したところ、3つの `verification` フラグはすべてtrueでした。これは**保存されているフラグの集計**であり、コードの全件再実行ではありません。生成スクリプトは3フラグがすべてtrueのレコードだけを保存候補に残します。学習・評価の読み込み時にも不合格やフラグ欠落を除外し、除外件数を警告します。

[scripts/evaluate.py](../../scripts/evaluate.py) は通常・言い換え・組合せの各問題で、固定入力集合と重複しないhidden入力を20件以上作って参照コードと比較します。`--hidden-count` と `--hidden-seed` で件数・seedを指定でき、問題文ごとに再現可能です。`--out` のレポートには実際の入力も記録します。固定148入力と境界値20入力の合格率は比較用に別集計し、境界値の全体率は評価した例数で加重します。過去の評価結果は固定入力基準のままで、再評価が必要です。

## 利用上の限界

- 固定入力・hidden入力とも有限のテストであり、全入力での等価性の証明ではありません。学習中の生成評価には構築時と同じ固定probeを使い、最終評価には別のhidden入力を使います。
- 退化例のsplit横断重複、異なる操作列の同一挙動、特殊テストとの挙動重複が残り得ます。
- データ生成時のトークン長フィルタは未実装です。訓練イテレータは `max_seq_len` 超過で例外を送出し、切り詰めません。
- 特殊テストは各30件と小規模で、言い換え側の対象opも限定されます。
- 既存の外部コードとの長い一致を検査する仕組みはありません。構文を限定することは、一致がないことの証明にはなりません。

## 再生成

承認済み辞書と由来対応表を保持したまま、リポジトリルートで実行します。

```bash
python -m scripts.build_probe_set
python -m scripts.build_ast_corpus
python -m scripts.build_dataset --seed 0 --workers 32
```

`--workers 32` は指定例で、保存済みデータの生成条件を証明するものではありません。再現時はseedだけでなく、元のワーカー数、コード、辞書、probe set、依存環境も揃えてください。コマンドは出力先の既存JSONLを上書きします。
